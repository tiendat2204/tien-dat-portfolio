## What is Scroll Stage?

A pinned section whose scroll position becomes numbers on the stage element, as CSS custom properties. Anything inside can be styled as a `calc()` of them, so a diagram draws itself, a packet travels, a result fades in, and React never re-renders while you scroll.

| Variable | Meaning |
|----------|---------|
| `--p` | Progress through the stage, 0 to 1, exactly as scrolled. |
| `--ps` | The same progress, eased: it trails the scroll a little and settles, so effects feel weighted instead of snapping. |
| `--v` | How fast it is still moving, -1 to 1 and 0 at rest. Use it for skew, blur or stretch while someone scrolls fast. |

Give the stage `chapters` and it also shows a numbered strip under the content, sets `data-chapter` to the active index, and scrolls to a chapter when its cell is clicked.

It plays three ways, chosen from the viewport:

- **Pinned** on wide screens: the stage pins and the scroll scrubs `--p`.
- **Stacked** on narrow screens: no pinning; `--p` plays from 0 to 1 once when the stage comes into view.
- **Static** with `prefers-reduced-motion`: `--p` stays at 1, so people see the finished state.

Before scripts run, `--p` is 0, so a stage starts empty instead of flashing its end state.

## Usage

Wrap your content in `ScrollStage` and style it with the helpers. Each helper takes a progress range: the effect holds its start state before `a` and its end state after `b`.

```tsx
import { ScrollStage, draw, fade, pulse, rise, travel } from '@/components/ScrollStage/scroll-stage'

export function Pipeline () {
  return (
    <ScrollStage topOffset={96} distance={1.5}>
      <svg viewBox='0 0 400 160'>
        {/* 0 - 0.3: the track draws in */}
        <path d='M30 80H370' pathLength={1} stroke='currentColor' fill='none' style={draw(0, 0.3)} />

        {/* 0.3 - 0.7: a packet runs along it, visible only while it moves */}
        <rect x={26} y={74} width={12} height={12} style={{ ...travel(0.3, 0.7, 340), ...pulse(0.28, 0.74) }} />

        {/* 0.7 - 0.9: the result appears */}
        <text x={262} y={122} style={rise(0.7, 0.9, 0, 10)}>result: ok</text>
      </svg>
    </ScrollStage>
  )
}
```

Any element can use the variables directly, no helper needed:

```tsx
{/* a bar that trails the scroll */}
<div style={{ width: 'calc(var(--ps) * 100%)' }} className='h-1 bg-foreground' />

{/* a block that skews while you scroll fast, and rests when you stop */}
<div style={{ transform: 'skewX(calc(var(--v) * -12deg))' }} />
```

### Chapters

Name the parts of the scroll and the stage shows them as a strip (they are ordered by `at`, whatever order you pass them in). The active chapter is inverted, a cell scrolls the stage to where its chapter starts, and the stage gets `data-chapter` so CSS can react to it.

```tsx
const chapters = [
  { at: 0, label: 'track' },
  { at: 0.3, label: 'packet' },
  { at: 0.7, label: 'result' },
]

<ScrollStage chapters={chapters}>…</ScrollStage>

// style by chapter from anywhere inside the stage
// [data-chapter='2'] .badge { opacity: 1 }
```

### Helpers

| Helper | Effect |
|--------|--------|
| `seg(a, b)` | A CSS number: 0 until `a`, 1 from `b`, linear in between. The others are built on it. |
| `draw(a, b)` | Draws an SVG shape in from its start. Put `pathLength={1}` on the element. |
| `fade(a, b)` | Fades opacity from 0 to 1. |
| `rise(a, b, dx?, dy?)` | Fades in while sliding from (dx, dy) px to its place. |
| `travel(a, b, dx, dy?)` | Moves from the origin to (dx, dy) px. |
| `pulse(a, b, edge?)` | Visible only between `a` and `b`, fading in and out over `edge`. |

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `distance` | `number` | `1.5` | How long the stage stays pinned, in viewport heights. |
| `topOffset` | `number` | `0` | Distance from the top of the viewport where it pins, e.g. a sticky header's height. |
| `pinFrom` | `number` | `1024` | Viewport width from which the stage pins. Narrower screens play once instead. |
| `duration` | `number` | `1` | Seconds the one-shot play takes on narrow screens. |
| `chapters` | `{ at: number, label: string }[]` | - | Named parts of the scroll (`at` is the progress where one starts). Adds the strip and `data-chapter`. |
| `scrollTo` | `(top: number) => void` | native smooth scroll | How chapter jumps scroll the page. Pass your smooth-scroll library's `scrollTo` (see Notes). |
| `onProgress` | `(progress: number) => void` | - | Called with each new progress value, e.g. to drive a canvas. |

Every other prop (`className`, `style`, `id`, …) goes to the stage's `div`. Use `useScrollStage(ref, options)` if you want the behaviour on an element you render yourself; it returns `goTo(progress)` to scroll a pinned stage to a progress value.

## Notes

### Smooth scrolling (Lenis)

ScrollStage listens to the page's scroll through GSAP's ScrollTrigger. With a smooth-scroll library, tell ScrollTrigger when it moves. With Lenis:

```tsx
import { useLenis } from 'lenis/react'
import { ScrollTrigger } from 'gsap/ScrollTrigger'

const lenis = useLenis(() => ScrollTrigger.update())

<ScrollStage chapters={chapters} scrollTo={top => lenis?.scrollTo(top)}>…</ScrollStage>
```

Pass `scrollTo` so chapter jumps go through Lenis. Lenis rewrites the page position every frame while it glides, so a native scroll started during a glide would be undone.

### Content that changes height

Images and lazy components change the page height after mount, which would leave pin positions stale. The stage watches its own size and re-measures once per frame, so you do not need to call `ScrollTrigger.refresh()` yourself.

### Pin spacing

While pinned the stage keeps its place and the page below waits for the pin to finish. Spacing is forced on, because GSAP otherwise turns it off when the parent is a flex or grid container and the next content would slide under the stage.

### Reduced motion

With `prefers-reduced-motion` the stage shows its finished state, `--ps` equals `--p` with nothing trailing, and `--v` is 0. Chapter cells still work as plain buttons.

### Stage state, not scroll position

`--p` is progress through *this* stage, 0 at the pin and 1 at its end, not the page's scroll offset. Several stages on one page each have their own `--p`.
